# 系列主文（Readme）

写 IP、系列、子系列、企划或作者作品群的总览时读这一份。一部具体作品走 `core.md` 的 9 章，不要因为它属于系列就写成主文。

本文件只管内容组织和层级判断，不管保存位置、数据库、审批和发布接口；宿主细节另读指定的适配说明。

## 1. 先判层级

| 层级 | 对象 | 这一页负责 | 这一页不写 |
| --- | --- | --- | --- |
| IP 级 | 一个完整 IP 或品牌 | 起源、创作史、介质版图、子系列索引、跨层关系、入门顺序 | 单作完整剧情、逐卷书目、完整 staff、子系列内部细史 |
| 子系列 / 企划级 | IP 下一条有独立概念、共享世界观或共同企划的分支 | 与父 IP 的边界、企划沿革、共享世界观、作品构成与计划演变、旗下索引 | 不属于本分支的载体、单作完整剧情 |

容易搞混的三种东西：

- **载体条目**：一部电影、剧集、动画、游戏、漫画或小说 → 走 `core.md` 的 9 章。
- **作品级简介**：一个复杂单作的可选总览，服务于多个版本或路线 → 不是 IP 主文，也不替代载体正文。
- **专题资料**：时代、技术史、访谈整理、世界观资料 → 跨多个对象时独立成文，不硬塞进主文。

层级不是越多越好。只有读者需要区分范围、顺序或关系时才加一层。

## 2. 动笔前先画对象树

从可靠来源列出：父 IP → 子系列 / 企划 → 独立作品 / 版本。给每个对象标四项：

1. 是不是独立发行单元；
2. 与其他对象是改编、续作、重制、衍生、共享世界观，还是仅再发行；
3. 当前有没有正文；
4. 需要独立条目，还是主文里一行带过。

已有条目的数量只说明建设进度，不能证明这个 IP 只有一种介质。不要把宣传短片、周边商品、普通外站页面当成载体。

## 3. 信息分配：同一事实只在一层展开

| 事实 | 归哪一层 |
| --- | --- |
| IP 起源、创作史、介质版图、子系列索引 | 父 IP 主文 |
| 分支的背景、共享规则、企划构成与演变 | 子系列主文 |
| 单作的版本、设定、完整剧情、机制、角色、评价 | 载体条目 |
| 同一部作品两层都要提 | 父页写定位和索引，子页写它在本分支里的作用 |

主文可以很详细，但「详细」指增加可核查的历史、关系、设定和因果，不是把每部作品的剧情段落重复一遍。

主文同样不回避剧透：系列主线、企划神话、关键转折和结局，只要是理解本层级所必需的就完整写。限制来自对象范围，不是「不能剧透」。

## 4. IP 级主文

标题写 `# <IP 名称> 系列索引`。首段一段话完成定位：名称与可核实别名、创作者或推出方、起点、核心故事或主题、主要扩展方向，末句声明「本页负责总览，单篇条目只讲自身」。首段不放某个版本的片长、卷数、ISBN、平台细节或未核实的销量。

```markdown
# <IP 名称> 系列索引

> 说明：本文范围、主要来源、资料截止日期、必要的剧透提示

## 作品概览
## 创作与发展（有足够史料时）
## 核心设定与系列主题（确有跨作内容时）
## 子系列与载体索引
### 游戏
### 影视 / 动画
### 漫画 / 小说
## 时间线与关系
## 阅读、观看或游玩顺序
## 其他载体或待建对象
## 事实来源
```

- 作品概览按「起源 → 核心概念 → 介质与阶段」展开，不展开单篇发行细节。
- 载体索引每行：对象名称 + 载体 + 关键日期（有来源才写）+ 一句定位；已完成与待建要能区分。
- 时间线与关系只写跨对象的接口和顺序，具体差异回到各载体条目。
- 顺序有多条路线时分路线写，不硬给唯一答案。
- 其他载体或待建对象只登记来源确认过、确实有独立身份的对象。
- 子系列多时先列子系列，再列没有更合适归属的独立作品。
- 图书合集可在索引后加「出版信息」和「分册一览」，列名与 `media-book.md` §5 一致。

## 5. 子系列 / 企划级主文

同一「系列索引」体裁，范围收窄：

```markdown
# <子系列或企划名称> 系列索引

> 说明：与父 IP 的关系、本文范围、主要来源、资料截止日期

## 子系列定位
## 创作背景与企划沿革
## 共享世界观与核心设定（适用时）
## 作品构成与计划演变
## 旗下作品索引
## 时间线、关系与顺序
## 与父 IP 及其他分支的接口
## 事实来源
```

- **子系列定位**：属于哪个父 IP、共享什么、又独立什么。
- **创作背景与企划沿革**：概念提出 → 正式公布 → 开发调整 → 最终落地。
- **共享世界观**：只在这个框架是读者理解本分支所必需时才写；可以详细写神话、规则、组织和因果，但每个断言要有来源，或明确标为推断。
- **旗下作品索引**：每行写作品身份、载体、实际发布信息、在本企划中的定位。单作的完整剧情和制作细节回条目。

「作品构成与计划演变」把这五种状态分开列，不要把宣传阶段的阵容当成实际系列：

| 状态 | 写法 |
| --- | --- |
| 计划中 / 概念阶段 | 写明这是计划，附公布时间与来源 |
| 已正式公布 | 公布日期 + 当时给出的信息 |
| 已发售 / 已播出 | 实际日期 + 载体 |
| 改名、转型、延期 | 旧名 → 新名 + 变更时间 + 依据 |
| 取消、脱离企划 | 写明何时、依据什么判断脱离 |

## 6. 事实与引用

事实域：名称与别名、起源、创作者、核心故事、世界观、作品版图、计划沿革、日期、关系、现状。核查强度按 `core.md` §6，另加两条：

- 「计划 / 公布 / 开发中 / 发售 / 重命名 / 取消 / 脱离企划」是七种不同状态，按来源和时间分别写，不能合并成一句；
- 索引行若直接取自已有条目、没有独立复核，在交付记录里标明「取自条目，未独立复核」，不要把旧条目自动升级成已核实事实。

## 7. 主文自检

- 标题和首段准确表明层级，父 IP 与子系列没有混写；
- 首段只有系列级定位，没有单载体的发行细节；
- 概览讲跨作品脉络，没有重复索引行里的完整事实；
- 每个索引行的名称都唯一指向一个实际对象，计划状态与发行状态没有混淆；
- 共享世界观和企划沿革写得够细，但没有无来源的动机、对白或剧情补造；
- 没有把某部作品的完整剧情、逐卷书目或完整 cast 压缩进来；
- 时间、销量、奖项、现状都带来源、口径和检索日期；
- 待核实项明确标注，未解决的来源冲突已列出；
- 没有顺带修改载体条目、创建关系或补齐缺失对象。

长度服从系列复杂度：大型 IP 或企划史丰富的子系列可以明显长于简短索引，但增加的应该是事实和结构，不是重复句子。

交付时可以附：主文全文；介质版图与对象状态表；「来源 → 事实」对照；未解决的冲突与待处理对象。
