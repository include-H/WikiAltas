# 跨介质作品 Wiki 写作

一套内容方法：写出结构固定、事实可核查、信息密度够、读起来像认真整理过的中文条目。本 skill 不规定数据库、接口、目录或审批流程。

## 第一步：先判断任务模式，再判断交付物

### 增量编辑模式

续写、补段、重写、压缩、润色和局部校订都属于增量编辑。此模式下：

- 不套 9 章骨架，不补齐缺章，不追求完整条目的字数区间；
- 只读取目标段、相邻上下文和任务明确需要的事实材料；
- 只加载 `core.md` 中与事实边界、文风和当前章节有关的规则，不能把整个 `core.md` 当提示词注入；
- 默认不读 `examples/`；样例只用于离线评测或人工校准；
- 输出只包含新增或替换的 Markdown，不复述整篇正文。

### 完整建档模式

从零撰写一篇完整载体条目时，才使用 9 章骨架、介质映射和全篇体量基准。系列主文和专题资料仍按下表选择规则，不强套载体骨架。

## 第二步：判断交付物，只读需要的文件

| 交付物 | 判断依据 | 读什么 |
| --- | --- | --- |
| 载体条目 | 对象是一部具体作品（一部电影、一部剧或动画、一款游戏、一部漫画或小说） | `core.md` + 一个介质文件 |
| 系列主文 | 对象是一个 IP、子系列、企划或作者作品群 | `core.md` §5–§8 + `readme.md` |
| 合集条目 | 对象是同一系列的多代编号作品、用户要求合写一篇（不逐代建档） | `core.md` + 一个介质文件 + `readme.md` §8 |
| 专题资料 | 对象是时代、技术、创作史、世界观资料等跨作品主题 | `core.md` §5–§8（不套 9 章骨架） |

介质文件**只读一个**：影视（电影、剧集、动画、OVA/OAD、剧场版）→ `media-video.md`；游戏 → `media-game.md`；漫画或小说 → `media-book.md`。同一 IP 横跨两种介质时，先说清当前这篇属于哪一种，另一种只在版本关系里点一句。

按需读取：

- `frontmatter.md`：任务要求结构化身份、别名、关系字段时。
- `wikiatlas-adapter.md`：任务明确要求 WikiAltas 字段、关系或正文落库时。普通写作不读。
- `examples/`：仅用于离线回归评测或人工检查信息密度；运行时模型默认不读。

## 六条硬规则

1. 只写任务指定的那一部作品、那一个层级。不顺手创建、修改或补全别的条目、关系和对象。
2. 事实、推断、评价分开写：事实要有来源；推断写明是推断；评价放在有证据的段落。
3. 查不到就写 `待核实`。绝不编造台词、日期、数字、奖项、ISBN、出处，也不用「据说」「广受好评」遮盖缺口。
4. **没有检索工具、或检索失败时，不要凭记忆填事实。** 不能核实的项写 `待核实`，并在交付说明里列出未核实清单。
5. 正文默认完整剧透（写到结局）。只有用户明确要求无剧透时才收敛。
6. 不从 skill 名、目录名、样例文件名推断当前写的是哪部作品、有哪些事实。

## 样例（examples/）

样例是**离线回归评测集**，运行时默认不读，也不能当 few-shot、事实模板或格式权威；只有人工明确要求对照某篇风格时，才截取与目标章节同类的少量段落，不能注入整篇。

- 规则与样例冲突时**以规则为准**；不复制样例里的作品名、日期、角色、评分、来源或段落。
- 写非游戏介质时按 `core.md` §2.2 取名，不要套游戏章名（样例偏游戏，且并非篇篇合格）。

逐篇判定与已知偏差见 `examples/README.md`（离线校准用，运行时模型不读）。

## 通用流程

1. 确认交付物、目标作品与介质、有没有无剧透例外、需要多深。
2. 读 `core.md` 和对应文件。
3. 先列事实域和待查问题，再检索核对，然后动笔。不要边写边凭记忆补。
4. 先写结构化事实和剧情，再写题记、评价和连接句。
5. 按 `core.md` §8 自检。没有明确落库要求时只交正文，不同步任何外部系统。
