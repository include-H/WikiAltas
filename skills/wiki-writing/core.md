# 通用写作核

写或改任何载体条目前先读这一份。介质差异见 `media-video.md` / `media-game.md` / `media-book.md`，**只读一个**；系列主文另见 `readme.md`。

本文件只管内容和格式，不管数据库、接口、目录、审批和外部服务。任务明确要求宿主字段或落库时才读指定的适配说明；没有明确要求就只交正文。

## 1. 开写前的四个确认

答不出就先查，不要边写边猜：

1. **交付物**：载体条目（一部具体作品）/ 系列主文（IP 或子系列）/ 专题资料（时代、技术、创作史）。判错会让整篇结构错。
2. **对象边界**：具体哪一部、哪个版本、哪一季？重制、特别篇、资料片、剧场版、合集算不算进来？
3. **剧透**：用户明确要求无剧透吗？没说就是写到结局的完整剧透。
4. **深度**：完整条目 / 只补某几章 / 只要概览。

确认结果写进正文开头的 `>` 说明行：整理范围、主要依据的来源、剧透提示。

## 2. 输出契约（格式硬要求）

### 2.1 载体条目骨架

```
# 作品名（载体）Wiki

> 说明：整理范围、主要依据的来源、剧透提示

:::epigraph
题记（写法见 §4）
:::

## 1. 作品概览
## 2. 基础信息速览
### 2.1 基本资料
### 2.2 版本关系
### 2.3 核心卖点
### 2.4 关键词
### 2.5 分卷/分册一览（图书需要逐卷查阅时才设）
## 3. 故事背景与设定
## 4. 剧情概要
## 5. 创作特色
## 6. 主要角色与创作团队
## 7. 评价与历史定位
## 8. 一句话总结
## 9. 参考资料
```

骨架规则：

- 一级章 1–9 固定、连续；不加第 10 章，不加 `## 引言`（题记已经承担这个功能）。
- 用不上的**小节**删掉后把同级小节重排，编号不留空号（例如没有版本可谈就删 2.2，原 2.3 变 2.2）。
- 章名可按介质替换（见 §2.2），编号不变。
- 小节标题要点出内容，例如 `4.2 平台转移的阵痛：主程序出走`；不用 `第一阶段`、`后续发展`、`其他`。

### 2.2 介质章名映射

| 编号 | 影视 | 游戏 | 漫画 / 小说 |
| --- | --- | --- | --- |
| 2.2 | 版本关系 | 版本关系（有 DLC 或资料片时可写「版本与 DLC 关系」） | 版本关系 |
| 3 | 故事背景与设定 | 世界观与背景设定 | 故事背景与设定 |
| 5 | 叙事与影像特色 | 玩法与结构特色 | 创作特色 |
| 6 | 主要角色与创作团队 | 主要角色与势力 | 主要角色与创作团队 |

不论哪种介质，**第 6 章的最后一个小节固定是关系简述**（`核心关系简述` / `关系简述` / `势力关系简述` 任选其一），用一小段点出理解本作最关键的 2–3 层关系。

### 2.3 字段行写法

一行一个字段：`- 字段名：值`。值里只有值，判断和解释不进字段。

- ✅ `- 首发日期：2011 年 11 月 11 日`
- ✅ `- 首发平台：Windows、PlayStation 3、Xbox 360`
- ❌ `- 首发日期：根据公开资料，本作大约在 2011 年底前后陆续登陆各主流平台。`
- ❌ `- 平台：多平台（覆盖很全）`

多值用 `、` 分隔；日期缺日写到月，缺月写到年；不要把三个字段挤进一句话。

### 2.4 缺口只有三种合法处理

| 情况 | 做法 |
| --- | --- |
| 查到了 | 写值，且能回到来源 |
| 查不到，但字段对读者重要（发行日期、卷数、集数、ISBN、导演、作者） | 值写 `待核实`，就这三个字，不加括号、不换说法 |
| 查不到，且字段本来可省（引擎、奖项、别名、插画） | 整行删掉 |

禁止：编造；按相近版本套用；用「据说」「据报道」「相传」「一般认为」「广受好评」把缺口糊过去。

### 2.5 参考资料

编号列表，每条写 `[来源标题](URL)`；纸质或线下来源写清出版物、版次和页码。默认 5 条以上，且让读者能分出哪条是官方材料、哪条是数据库、哪条是评论。只列真正用过的来源，不补凑、不编链接。

### 2.6 排版约定

- `---` 分隔线可有可无，但同一篇里保持一致：要么每章之间都有，要么都没有。
- 引用原文用 `「」` 或 `""`，同一篇只用一种。
- 中文与拉丁字母、数字相邻时两侧留一个空格。

## 3. 逐章要求与体量基准

下表的体量是**默认区间**，取自现有条目的实际分布，用来防止写得过薄。材料不够时按实际写短并在说明行交代，不要凑；材料确实丰富时可以超。任何情况下都不为了落进区间制造内容。

| 章 | 要回答什么 | 默认体量 | 最常见的写坏方式 |
| --- | --- | --- | --- |
| 1 概览 | 是什么、谁做的、何时发布、在哪条创作序列里、改编自什么、最大特点 | 3–4 段 | 写成剧情简介，或写成跨载体总目录 |
| 2.1 基本资料 | 可核查的身份字段 | 14–23 行 | 字段值里塞判断句 |
| 2.2 版本关系 | 这些版本到底是不是同一部作品 | 4–8 行 | 把移植、再发行、配音版写成新作 |
| 2.3 核心卖点 | 具体特征 | 5–6 条 | 写成宣传语 |
| 2.4 关键词 | 人名、地名、组织、系统、场景、曲名 | 10–12 个 | 写成短句而不是词 |
| 3 背景设定 | 时代、地点、社会结构、核心冲突、主角所处的结构位置、主题气质 | 2–4 段，或 2–3 个小节 | 提前复述剧情；开始评价好坏 |
| 4 剧情概要 | 完整事件链，一直写到结局 | 4–6 节，每节 150–500 字，合计约占全文 15–20% | 流水账；只写到中段；「最后真相大白」 |
| 5 创作特色 | 手法或机制 + 它解决什么问题 + 读者实际感受到什么 | 3–5 个小节 | 「镜头很美」「系统丰富」 |
| 6 角色与团队 | 读者必须认识谁，以及关系骨架 | 3–5 个小节，每个角色 1–2 句 | 退化成完整演员表 |
| 7 评价与定位 | 数据 + 争议 + 三层历史位置 | 3–5 段，或 3–4 个小节 | 只写「口碑很好」 |
| 8 一句话总结 | 全文收束 | 1–2 句 | 复读第 1 章 |
| 9 参考资料 | 实际用过的来源 | ≥5 条 | 列没用过的来源 |

全篇默认 5,000–11,000 字（不计空白）。

### 3.1 剧情章怎么分节

按作品自身结构选一种，选定后不再混用：电影按幕；剧集或动画按季、故事弧（可在小节标题里标话数区间）；游戏按主线阶段或阵营线；漫画、小说按卷或故事弧（可标卷号区间）。

每节写清：谁、在哪里、做了什么、为什么（只有来源支持时才写动机）、造成什么转折、结果如何。合并重复行动，保留能解释人物变化、规则变化和结局的节点。关键反转和结局要落到具体细节，不要用「若干冲突」「开放式结局」收束。

非线性作品先说明「播放/阅读顺序」和「故事时间线」哪里不同，再挑一种顺序稳定重述，并标出读者在哪一刻才知道某件事。

### 3.2 评价章的三层历史定位

分开写：① 对本系列或 IP 的意义；② 对创作者、团队个人序列的意义；③ 对类型、行业或媒介史的意义。

数据必须带平台、统计口径和检索时间；没有公开数字就跳过整项，不估算。争议要点名具体问题（结局处理、某条线的节奏、平衡性、选角、改编取舍、技术表现），并有公共讨论支撑，不写私人好恶。

## 4. 题记

题记是气质入口：**站在作品世界里说话，不站在世界外评论**。位置在 `>` 说明行之后、第 1 章之前，用且只用一个 `:::epigraph` 块。

### 4.1 先判断用哪一种

1. 这部作品有没有一句大家真的记得的台词、旁白、歌词或系统语音？
   - 有 → 先联网搜「作品名 + 名台词 / 名言 / セリフ / quotes」，拿到原文和出处再写【引用式】，并用两条互相独立的来源核对用字。
   - 核实不到 → 换第 2 种。**不要凭印象补台词，也不要先写一句再去找出处。**
2. 没有可核实的名句 → 【场景式】。这是最常用的一种。
3. 古装、武侠、仙侠、历史、神话题材 → 可以用【诗句式】。现代、写实题材不要硬写诗。

### 4.2 引用式

结构（逐句交替，缺一不可）：

```
<原文第一句>
<该句的中文>
<原文第二句>
<该句的中文>
——<角色名或旁白来源>《作品名》<集数或场景>
```

填好后大致长这样（内容是虚构示例，只看格式，不要照抄）：

```
:::epigraph
The bridge was supposed to hold until dawn.
那座桥本该撑到天亮。
It held for nine minutes.
它撑了九分钟。
——阿尔滕上士《北岭之桥》第 3 章
:::
```

硬规则：

- 每句原文都要有对应译文，**不是「原文整段 + 中译整段」**。确实需要整段配对时，两段之间空一行（空行是有意义的排版停顿），但每句仍要有译文。
- 一行只放一种语言。纯拉丁字母的行会渲染成小字（原文），含中文的行渲染成大字（中译）；同一行混排会让这层对照失效。
- 台词本来就是中文时直接成行，不需要译文。
- 最后一行是署名：`——` 开头、单独成行，至少写到角色名或旁白来源，能查到就补作品、集数或场景。署名行只标出处，不夹带评价。
- 真正出圈的长台词宁可整段引全，不为凑行数截掉后半句。

### 4.3 场景式

从作品世界内部写 2–6 行：地点、天气、物件、人物正在经历的某个瞬间。虚构示例，只看写法：

```
:::epigraph
雨从三月下到四月，铁皮屋顶一直在响。
他把最后一封没寄出的信压在秤盘底下，
称完那天最后一斤盐，才熄了灯。
门外的路，已经泡得看不出方向。
:::
```

- 默认写中文，不跟随作品原语言。
- 每行都要有具体画面：地名、天气、物件、动作、职业细节。
- 人物的过去和使命靠意象暗示，不复述剧情，不揭关键反转。
- 结尾留一句有余味的收束，不把话说满。
- 场景式是自己写的，**不加署名行**。

### 4.4 诗句式

四句、节奏整齐（常见七言）。读完能看出讲的是谁、经历了什么、最后留下什么，必须落到具体人物和事件。虚构示例：

```
:::epigraph
渡口烟深旧酒旗，
剑归鞘冷雁南飞。
一诺换来十年错，
碑前无字可分辨。
:::
```

不堆「江湖」「宿命」「山河」这类空词。自创诗句不加署名行。

### 4.5 禁区（出现即整段不合格）

- 主语是作品：「这款游戏」「这部剧」「本作」。
- 拿别的作品作比较：「比前作」「初代」「这一季终于」。判别法——**指作品结构的指称出局**（第 X 部、初代、前作、第一季、续作）；**指世界内时间的指称允许**（多年之后、战争结束后的那个冬天、又一次）。
- 谈发行、销量、市场、制作流程、行业地位、改编取舍。
- 换成任何一部同类作品也完全成立的空句。
- 引用式缺译文、缺署名行，或署名行里夹带评价。

## 5. 文风：改前 → 改后

| ❌ 这样写 | ✅ 改成这样 |
| --- | --- |
| 这款神作的战斗系统简直是封神级别的天花板 | 战斗把格挡、弹反和体力条绑在同一套节奏上，逼玩家在攻防之间反复取舍 |
| 你会发现导演其实想说的是权力的代价 | 导演在三场审讯戏里重复同一机位，把权力关系压成固定构图 |
| 表面上是一部冒险片，真正讲的却是成长 | 冒险线推进的同时，主角三次拒绝求援，最后一次才开口 |
| 本片获得众多奖项与好评 | 本片获第 84 届奥斯卡最佳影片提名；Metacritic 均分 84（32 家媒体，检索于 2026-09） |
| 剧情最后真相大白，结局令人回味 | 结局揭穿委托人本人就是纵火者，主角销毁证据并辞去职务 |
| 画风精美，音乐震撼 | 每卷开篇用两页无对白全景交代季节变化；同一段主题旋律出现在三次死亡场景 |
| 系统丰富，玩法多样，可玩性极高 | 主线之外有四条公会线，各有独立任务链和结局，可在同一周目并行推进 |

另外：

- 用第三人称陈述，不写「你会看到」「我们不难发现」。
- 少用连续论证套句：「不是……而是……」「换句话说」「也正因为如此」；章节标题里禁用。
- 每段至少落在一个具体对象上：人名、地名、日期、机制、镜头、出版信息或来源。
- 同一个事实只在最合适的一章完整出现一次，别的章最多一句指向。
- 长度服从信息量。写不动就说明缺什么材料，不要用同义句扩写。

## 6. 事实核查

### 6.1 来源分层

| 层级 | 用来支撑什么 | 典型 |
| --- | --- | --- |
| 一手 / 官方 | 身份、日期、主创、版本、官方设定 | 官网、发行方或出版社页面、原作文本、官方商店页、颁奖机构公告 |
| 专业数据库 / 权威媒体 | 交叉核对、补齐结构、评分与商业数据 | 综合百科、作品数据库、行业统计站、专业媒体报道 |
| 社区与自媒体 | 只作线索，用来知道该去查什么 | 论坛帖、解说视频、粉丝站、影评书评 |

第三层不能单独支撑任何关键断言。**「两条独立来源」指信息链路独立**：同一内容的不同语言版本、互相转载的站点、抓同一个数据库的页面，都只算一条。

选来源要看它是否真的覆盖这部作品所在的市场和语区；不要因为上面的例子里没列就漏掉更权威的官方来源。

### 6.2 三档核查强度

| 事实类型 | 强度 |
| --- | --- |
| 身份类：作品名、主创、首发日期、平台、集数或卷数、版本关系 | 至少一个权威出处；关键项再找一条独立来源交叉确认 |
| 细粒度类：逐字台词、事件归到第几集/卷/场、各种计数、人物亲属关系、逐卷卷名与 ISBN | 写完后**逐条**回原始材料核对，不能抽样 |
| 数字与时间点：评分、票房、销量、奖项、「截至某日」的现状 | 记统计口径 + 检索时间；来源冲突就继续查，查不动则并列争议或标 `待核实` |

剧情章先用官方简介、原作文本、节目资料或作品内文本建立事件链，再写概括。没有来源支持的动机、动作和对白，删掉或降级成「未说明」。

### 6.3 事实账本

全程维护一张简表：断言 / 来源 / 状态（已核实、冲突、待核实）。交付时可以附上，并列出未解决的冲突和待核实项。

### 6.4 没有检索能力时怎么办

**没有检索工具，或检索失败、结果不可用时，不要凭记忆把事实补齐。** 记忆里的日期、集数、销量、奖项、台词、ISBN 有相当比例是错的，而错误的具体数字比空缺更难被发现和修正。

此时的正确做法：

1. 结构、章节、剧情框架照写——这些不依赖外部检索；
2. 所有需要来源的具体值写 `待核实`，宁可整章只有结构；
3. 在 `>` 说明行和交付说明里写清「本篇未联网核实」，并列出待核实清单；
4. 题记退回场景式或诗句式，**不要写引用式**——引用式的前提就是拿到了可核对的原文。

用户只给了一个作品名、信息不足时：先检索；检索不到再问，不要先编一版等着被纠正。


## 7. 边界

### 7.1 载体之间

- 一篇条目只写自己这一部的版本、剧情、机制、角色和评价。
- 改编来源：在 2.1 字段、第 1 章一句话、第 5 章「与源作品的差异」里交代，不代写源作品的剧情。
- 兄弟载体（同 IP 的其他游戏、影视、图书）：只在 2.2 说明时间线和接口，不搬运它们的剧情和资料表。
- 系列级发行史、全部载体清单、跨载体关系、观看或阅读顺序 → 系列主文（`readme.md`）。
- 外部平台的对象、资源页、OST、攻略、访谈不是条目，只能作为来源或附注。

### 7.2 要不要独立成篇

依次问四题：① 有独立的发行身份吗？② 叙事上能单独看懂吗？③ 版本差异大到影响理解吗？④ 读者会单独搜它吗？

两个以上「是」→ 独立成篇；否则并进主条目的版本关系，或系列主文里的一行索引。不用固定季数、卷数阈值，也不用固定作品名单。

### 7.3 不做的事

写一篇条目不会顺带创建兄弟条目、补关系、改别的条目、同步外部服务——除非用户明确要求。

## 8. 交付前自检

逐条都要能答「是」，答不出就回去改：

1. 一级章 1–9 齐全、编号连续；小节删除后没留空号；没有 `## 引言`。
2. 章名按 §2.2 的介质映射替换正确；第 6 章最后一节是关系简述。
3. 题记在 `:::epigraph` 块里；引用式有逐句译文和署名行，场景式与诗句式没有署名行；没有 §4.5 的禁区句。
4. 每个字段独立成行、值里没有判断句；所有缺口是 `待核实` 或整行删除，没有编造。
5. 剧情写到结局（除非用户要求无剧透），分节符合作品结构，没有流水账，没有未说明的时间线跳跃。
6. 版本关系没有把移植、再发行、配音版、合集写成新作。
7. 兄弟载体和源作品只留了接口，没有被展开成第二篇条目。
8. 文风扫过一遍：第二人称、空泛赞美、套话连接词、无依据的评价都清掉了。
9. 评分、票房、销量、奖项带平台、口径和检索时间；细粒度事实逐条核过。
10. 参考资料真的支撑正文，每个关键断言都能回到事实账本。
11. 没有为了凑体量区间、模仿样例、迁就某个字段而写入无关内容。

改多篇时：先跑一遍结构与事实扫描留下基线，再改；机械格式替换和内容判断分两步做，避免把一个错误复制到整组。
